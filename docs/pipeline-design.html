高斯场景 Mesh 单体化流水线

从场景高斯与场景 mesh 出发，把每个物体变成可放进具身仿真的独立 mesh 资产，位置、朝向、尺寸与原场景一致。本文定义每一步的输入、处理、通过条件、失败动作与降级路径。

日期 2026-11-26状态：待评审阈值均为初始值，需用标注集校准（见 05）

三条设计原则

1. 主流程是确定性状态机，LLM/VLM 只在判断节点调用，codex-app-server 只处理异常诊断。

2. 每个关卡先看数值指标，指标落在模糊区间才调用 VLM，省钱也更稳定。

3. 每个物体在任何一步失败都有确定的降级去向，场景永远能产出完整的仿真资产。

01坐标系与数据约定

放回场景能否做准，取决于三个坐标系的约定是否清楚。所有变换矩阵都写进物体记录，任何一步都能复现。

坐标系定义由谁确定
W 场景系Z 轴朝上（逆重力），单位米，地面 z = 0S0 校正后统一，所有原始数据先乘 T_norm
O 物体规范系原点在物体底面中心，+Z 朝上，+X 为物体"正面"方向S5 选定 Front 视角时确定，记录 T_WO
M Rodin 输出系文档约定 +Y 为高度轴；正面朝向待实验 E1 确认E1 实验得到常量 R_conv（M → O 的轴变换）

02产物分级

不转人工，所以失败的物体也要有产物。分级结果写在物体记录里，抽检时按置信度从低到高看。

等级视觉 mesh碰撞体何时使用

L2从场景 SLAM mesh 裁出 + 高斯颜色烘焙CoACD 凸分解生成或放回失败，但物体几何可从场景 mesh 获得

S0场景入库校验

目的：保证场景坐标系是重力对齐、真实尺度的，并且场景 mesh 和高斯互相重合。这一步不通过，后面全部不做。

输入
  • 场景高斯 ply、实例 ID、语义标签
  • 场景 mesh（SLAM 输出）
  • 相机位姿
输出
  • T_norm（旋转 + 平移 + 尺度）
  • 地面、墙面平面参数
  • scene.json
  1. 地面检测：在场景 mesh 上做 RANSAC 平面拟合，选法线与当前 up 轴夹角小于 30°、位置最低、面积最大的平面。求旋转把地面法线对齐到 +Z，平移使地面 z = 0。
  2. 墙面检测：剩余点做多次 RANSAC，保留法线水平（与 Z 夹角 > 80°）、面积 > 1.5 m² 的平面，记录法线（朝向室内）。
  3. 尺度校验：对语义类别有稳定尺寸的物体（门高约 2.0 m，桌面约 0.72–0.76 m，椅面约 0.42–0.48 m，床高约 0.45–0.6 m），用测量值与先验的比值取中位数 r。参与的物体少于 3 个时，只做记录，不做校正。
  4. mesh 与高斯一致性：取不透明度 > 0.5 的高斯中心，计算到场景 mesh 的距离。

S1物体清单

把每个实例 ID 整理成物体记录，过滤掉不需要单体化的部分。

  • 计算每个实例的高斯数量、平均不透明度、重力对齐 OBB（先投影到水平面求最小面积外接矩形得到 yaw，再取 z 范围）。尺寸用 P2–P98 分位数，排除漂浮点。
  • 结构类标签（墙、地、天花板、窗、门框）不进入后续流程，记为场景结构。
  • 对角线 < 3 cm 或高斯数 < 200 的实例：标记为"微小物体"，默认并入支撑物或忽略（可配置）。
  • 单个实例的高斯在空间上明显分成多块（DBSCAN 后有 ≥ 2 个大簇）：标记 suspect_multi，交给 S4。

S2区域与支撑关系

区域判定（逐物体）

  • 计算物体 OBB 底面四条边到每面墙的最近距离，阈值 d_wall = 0.20 m。
  • 与两面夹角 > 60° 的墙都近 → C；只与一面墙近 → B；都不近 → A。
  • 区域只是先验。实际能看到哪些面，以相机覆盖为准：对每个相机做 mesh 光线投射判断物体是否可见、未被遮挡，按水平方位角分 8 个桶（每桶 45°）统计覆盖。记录 observed_bins，后面选视角和判断"哪些面要猜"都用它。

支撑关系

  • 对每个物体，在其底面下方找最高的水平支撑面：地面，或另一物体的顶面（在该物体顶部高斯上拟合水平平面，且两者水平投影重叠 > 50%）。
  • 输出场景内的支撑 DAG。S8 按拓扑序处理：先放桌子，再放桌上的杯子，杯子的支撑高度取桌子最终 mesh 的顶面，保证不悬空、不穿插。
  • 出现环（理论上不应出现，通常是分割错误）：断开置信度最低的边并记录。

S3漏检补全

两条路径。默认只跑 3D 残差；残差高斯比例偏高的场景才开启 2D 路径，以节省 CPU。

路径一：3D 残差

  1. 场景高斯 − 所有实例高斯 − 距离墙面或地面 3 cm 以内的高斯 = 残差高斯。
  2. 残差高斯做 DBSCAN（eps = 3 cm，min_samples = 50）。
  3. 簇满足以下全部条件时成为候选：对角线 ≥ 5 cm；平均不透明度 ≥ 0.4；厚度 ≥ 1 cm（排除贴画、插座面板这类平面物）。

路径二：2D 多视角（按需开启）

  1. 从真实相机位姿中选 12 个均匀分布的视角，以 512 px 渲染 RGB 和实例 mask。
  2. CPU 上跑轻量开放词汇检测加 MobileSAM 分割，找出没有被任何实例 mask 覆盖、面积 > 0.5% 画面的区域。
  3. 把每个残差高斯投影到各视角，统计落进同一未覆盖区域的次数。≥ 3 个视角一致的高斯组成候选。

确认

把本场景所有候选拼成一张网格图（每格是候选物体的裁剪图加红色描边），一次 VLM 调用返回 JSON：每个候选是否为独立物体，类别是什么。

S4多物体拆分

触发条件（满足任一）

  • S1 标记 suspect_multi：DBSCAN 后有 ≥ 2 个簇，每个簇占比 ≥ 15%。
  • 尺寸与类别不符：OBB 超出该类别尺寸范围的 1.5 倍。
  • 高度方向出现多个水平分层（高度直方图有多个峰，典型如书堆）。
  • 以上信号都模糊时，才调用 VLM 数物体个数（带物体 mask 描边的 3 个视角，一次调用）。

拆分方法（由便宜到贵）

  1. 3D 聚类：物体之间有空隙，DBSCAN 直接拆开。
  2. 水平分层：书堆、叠放的盒子，按高度直方图的谷底切开，每层再做水平聚类。
  3. 2D 投票：物体贴在一起时，渲染物体自身高斯的 6–8 个视角，MobileSAM 分割后跨视角匹配 mask（用重叠高斯的数量做匹配），每个高斯按多数票归属。得票率 < 60% 的边界高斯，按距离分给最近的子物体。

S5选视角与路由

候选视角

  • 优先用真实相机位姿：高斯在训练视角附近渲染质量最好，偏离越远越模糊。有原图时直接用原图，没有就用高斯渲染图。
  • 真实视角不够时，在 observed_bins 范围内补充虚拟视角，但与最近的真实视角夹角不超过 20°。
  • 每个视角渲染物体自身高斯（RGBA，背景透明），按物体外接框裁剪并留 10% 边距，统一缩放到 1024 px。

视角质量分

q = 0.35·未遮挡比例 + 0.25·清晰度(拉普拉斯方差，按场景归一化)
  + 0.20·物体像素占比得分 + 0.20·未被画面边缘截断
未遮挡比例：用场景 mesh（挖掉物体自身）做光线投射，判断物体像素前方是否有其他物体

选 3–5 张：先选 q 最高的一张作为 Front 候选，之后贪心地选择与已选视角最小夹角最大且 q ≥ 0.6 的视角。

确定物体规范系 O

  • Front 方向：q 最高视角的相机方向投影到水平面，取反（物体朝向相机）。如果与 OBB 某条水平轴的夹角 < 20°，吸附到该轴。B 类物体优先用墙面法线（指向室内）。
  • 其他视角按相对方位角打标签：F / FR / R / BR / B / BL / L / FL；俯视大于 45° 记 U，仰视记 D。这些标签直接作为 Rodin 的 image_label。

S6生成补全视角（GPT 生图）

GPT 生图支持多图参考和自定义尺寸，但没有深度或轮廓这类硬几何约束。所以几何一致性由我们的后置检查保证，不指望模型自己做到。

目标视角集合（最终送 Rodin 5 张）

类别必须包含原因
默认F、R、B、L + 一个 U覆盖四周和顶部
杯、碗、瓶、花盆F、R、B、FL 斜俯视 + D（底部）底部最容易生成错
椅、沙发、凳F、B（背面）、L、R、FR 斜俯视椅背背面最容易出错
B 类靠墙物体F、L、R、U + B背面一定看不到，需要推测

类别表做成配置文件，可以持续扩充。真实视角已经覆盖的标签直接用真实渲染图，只生成缺失的标签。

生成方式

  1. 一次调用生成一张 3×2 网格图（2048×1365 左右）。输入 3–5 张真实渲染图作为参考，每张注明对应标签。
  2. 提示词要点：同一个物体，几何形状与参考图完全一致；中性灰背景；均匀漫射光；物体居中且大小一致；每格对应哪个视角方向；看不到的部分按该类物体最常见的结构推测，不添加参考图里没有的部件。
  3. 切分网格，去背景（灰底阈值加 CPU 抠图模型），得到每个视角的 RGBA。

调用流程

  1. 提交前先写一条"待提交"记录（幂等键 = 输入图哈希 + 参数哈希），重复调度时直接复用，不会重复扣费。

  3. 轮询状态，退避间隔 10 s → 20 s → 40 s → 60 s 封顶；超过 20 分钟视为超时。
  4. 下载 glb，存对象存储。

S8放回原场景（核心）

目标：求一个相似变换 T_WM = [s·R | t]，把 Rodin 输出的 mesh 从 M 系放到场景 W 系，使它和物体高斯在位置、朝向、尺寸上都对齐，同时满足仿真的物理约束。

v0.2 修订：v0.1 的 S8 在一个真实房间（左床、茶柜、茶托、两瓶水）上实测，五件全部降级为 L3。暴露出的问题与对应修改汇总在 8.8，正文中标注"v0.2"的条目是本次新增或改动。

输入
  • Rodin mesh（M 系）
  • 物体高斯点 G（W 系，已去漂浮点）
  • OBB、axis_confidence、T_WO
  • 支撑面高度 h_s，相邻墙面
  • S5 选出的真实视角（位姿 + 该相机的真实内参与畸变 + 物体 mask）
  • 场景 mesh（已挖掉本物体）+ 已放置的物体 mesh
  • v0.2：extent_scope（物体范围约定，见 8.1）、bbox_condition；替换已有摆放时，还要输入原摆放 T_WM_baseline
输出
  • T_WM_final
  • 各项对齐指标与置信度
  • 通过 / 重试 / 降级的决定

8.0 变换的参数化

绝大多数室内物体是正放的，所以旋转只保留绕竖直轴的 yaw，把 7 个自由度降到 5 个：

T_WM = Translate(tx, ty, tz) · Rz(ψ) · Scale(s) · R_conv · Translate(-c_M)

R_conv : M 系到 O 系的固定轴变换（Y-up → Z-up，Rodin 正面轴 → +X），由实验 E1 确定
c_M    : mesh 在 R_conv 后的底面中心（包围盒 x、y 中心，z 最小值）
待求    : s, ψ, tx, ty, tz        （tz 基本由支撑面确定）

倾倒、斜靠的物体（S1 中 OBB 主轴明显不竖直，或 VLM 判断为倾倒）单独标记，允许额外两个倾斜角，搜索范围 ±30°。这类物体比例很低，第一版可以直接走 L2。

8.1 预处理

v0.2：先统一"物体范围"（extent_scope）

实测中床的尺寸估计、IoU 结论反复变化，根本原因是"什么算这个物体"在各处口径不一致：实例高斯和人工轮廓都带上了固定在墙上的床头软包，任务要求却是把它排除；Rodin mesh 里有没有床头板又是另一回事。所以测尺寸、算 IoU、算 Chamfer 之前，先把范围定死：

  1. 按类别配置表确定包含和排除的部件，例如床 = 床架 + 床垫 + 被褥，排除固定床头软包、背景墙；柜 = 柜体，排除柜面上的独立物体。结果写进物体记录 extent_scope。
  2. 高斯、S5 的评估 mask（eval_mask）、S7 的 bbox_condition、mesh 的测量区域，全部用同一份 extent_scope。被排除部件的像素在 eval_mask 里标为"忽略"，既不算前景也不算背景。
  3. 范围裁剪的自检：裁剪后高斯在各真实视角的重投影，要覆盖该视角 2D 分割中"应包含部件"的 ≥ 95%。实测中新的床主体筛选丢掉了部分被褥，属于这一检查要拦下的情况。
  4. mesh 里有、但范围要求排除的部件（例如 Rodin 生成了床头板）：在 mesh 上按高度或连通分量切掉后再测量；切不开就在 mesh 侧也标为"忽略区域"，不参与尺寸和 Chamfer。

mesh 侧

  1. 加载 glb，合并子网格，删除面积占比 < 1% 的连通分量。
  2. 应用 R_conv，平移使底面中心在原点，得到规范 mesh M₀。
  3. 记录 M₀ 的包围盒尺寸 (e_x, e_y, e_z)，在表面均匀采样 2 万个点，建 KD 树。
  4. 建 Open3D RaycastingScene，供后面渲染轮廓和计算穿插使用。

高斯侧

  1. 取不透明度 > 0.3 的高斯中心，做统计离群点剔除（20 邻域，2σ）。大尺度高斯可以沿主轴额外采样 2–3 个点，让表面更连续。
  2. 变换到 O 系（乘 T_WO⁻¹），在各轴上取 P2 和 P98 得到稳健尺寸 (E_x, E_y, E_z)。
  3. 高度不用高斯最低点：底面通常看不到，还容易有漂浮点。高度 H = P99(z) − h_s，以支撑面为基准，且只用 extent_scope 内的高斯。
  4. v0.2：有"参考顶面"的类别用顶面而不是 P99。床取床垫顶面，桌取桌面，柜取柜顶：在范围内高斯的上部拟合面积最大的水平面作为 H，mesh 侧用同样方法取 e_z。实测中床高被估成 1.05 m（混进了床头软包），改为床主体后是 0.61 m。
  5. v0.2：独立的真实视角尺寸测量。用 S5 真实视角的 eval_mask 和真实内参做 visual hull，在 O 系测出各轴尺寸 (V_x, V_y, V_z)。visual hull 只会偏大，所以它是上界，用来检查高斯尺寸是否偏小（实测中三个源图视角量到床宽 1.42–1.51 m，候选只有 1.24 m）。
  6. axis_confidence：某个轴两端都被看到（两侧方位桶都有覆盖）才算可信，例如 B 类物体的前后方向通常不可信。

8.2 尺度

s_z = H   / e_z              高度轴，几乎总是可信
s_x = E_x / e_x              仅当 axis_confidence.x ≥ 0.7
s_y = E_y / e_y              仅当 axis_confidence.y ≥ 0.7
s0  = 可信轴上的加权中位数，权重 = axis_confidence
  • 因为 S7 传了 bbox_condition，几个可信轴的 s_i 应该接近。最大值和最小值之比 > 1.10 时，按下面的情况处理：
    • x 和 y 的比值正好接近互换：说明 Rodin 的正面朝向和预期差了 90°，把 ψ 候选加上 ±90°，交给 8.3 处理。
    • 不是互换：说明生成的比例不对。允许每轴不超过 5% 的各向异性修正（在 S9 做）；超过 5% 时，在预算内带同样的 bbox_condition 重新生成一次，否则转 L2。
  • 高度不可信（顶部被柜子挡住、物体挂在墙上）：改用最可信的水平轴。
  • 语义合理性（v0.2 改为硬约束）：缩放后的任何一个尺寸超出类别范围（例如床长不在 1.8–2.3 m，椅子高度不在 0.6–1.2 m），不允许继续用这个 s0：去掉造成超限的轴重算；只剩一个可信轴时，用类别先验和 visual hull 上界夹住 s0。v0.1 只降低置信度，实测中一个错误的床高把三个方向一起放大到 3.61 × 2.13 m，这一条应当直接拦下。
  • v0.2：只有一个可信轴时必须交叉验证。等比缩放会把单轴的错误放大到所有轴，所以至少再有一个独立来源（visual hull、类别先验、bbox_condition）与之相差 ≤ 10%，否则标记"尺度存疑"并且不能判 L1。

v0.2：允许有限的分轴缩放

实测中床的长度对了（2.07 m），宽度却偏窄约 15%（1.24 m 对 1.42–1.51 m），任何等比缩放都无法同时满足两轴。v0.1 只允许 S9 做 ≤ 5% 的各向异性修正，对没有 bbox_condition 的资产太紧。改为：

  • 箱形家具（床、柜、桌、书架，可配置）在 8.5 中把尺度扩展成 (s_x, s_y, s_z)，各轴相对 s0 的偏离 ≤ 12%，并加正则项。其他类别保持等比，各向异性仍在 S9 做，上限 5%。
  • 只对可信轴分轴缩放；不可信轴跟随 s0。
  • 偏离超过上限：有 bbox_condition 时说明生成比例不对，重新生成；资产没有 bbox_condition（例如历史资产）时，记 ASSET_NO_BBOX_CONDITION，按生成问题处理，不算放回失败。

8.3 朝向（yaw）：先给候选，再打分

不盲目搜索 360°，先用先验生成少量候选：

来源候选角可信度
Front 视角先验ψ_F：O 系 +X 在 W 系中的方位角（Rodin 按 image_label 正确生成时，这就是答案）最高，E1 实验验证后可作为主候选
OBB 主轴θ_obb + k·90°，k = 0..3家具通常沿主轴摆放
墙面B 类：墙法线方向；C 类：两面墙的法线方向靠墙物体通常背对墙
兜底每 15° 一个，共 24 个只在以上候选得分都低时使用

快速打分

对每个候选 ψ：用 8.2 的 s0，z 贴合支撑面，xy 放到高斯可见部分的水平中心，然后计算：

score(ψ) = 0.5 · IoU_mean            K 个真实视角下，mesh 轮廓与高斯 mask 的平均 IoU
         + 0.3 · (1 − min(1, D_G→M / (0.05·diag)))   单向 Chamfer，见下
         + 0.2 · color_sim           可选：mesh 纹理渲染图与高斯渲染图的低分辨率颜色相似度
  • 轮廓渲染在 CPU 上：用 RaycastingScene.cast_rays 以 128 px 分辨率逐像素发射光线，命中即为 mask。4 个视角约 6.5 万条光线，单次几十毫秒。
  • 单向 Chamfer D_G→M：只计算"每个高斯点到 mesh 表面的距离"，不反过来算。高斯是残缺的（背面、底面缺失），mesh 是完整的，双向 Chamfer 会惩罚 mesh 上那些本来就看不到的部分。取截断均值（超过 5 cm 的点按 5 cm 计，防止漂浮点主导）。
  • IoU 只在可信视角上算：只用 S5 中 q ≥ 0.6 的真实视角，并且只统计未被其他物体遮挡的像素。
  • v0.2：IoU 的参照必须固定。所有候选（包括原摆放）都对同一份 eval_mask 计算，忽略区域不参与。实测中同一组候选，用人工画的轮廓（含床头板）和用本次提取的床主体轮廓算 IoU，排序相反（原摆放 0.829 / 0.742，新候选 0.731 / 0.759），说明换参照得到的数字不可比。eval_mask 按内容哈希版本化，结果里记录用的是哪一版。
  • v0.2：用真实内参渲染。轮廓渲染使用该相机自己的内参和畸变参数。缺少内参的视角不参与 IoU；实测中用统一假设内参重渲染，IoU 本身就带系统误差。

对称歧义

  • 前两名候选的得分差 < 0.03，且角度相差约 180° 或 90°，判定为对称歧义。几何无法区分时，用颜色项 color_sim 决定（例如有图案的一面）。
  • 颜色也无法区分（纯色对称物体）：选离 ψ_F 最近的候选。这种情况下朝向错了对仿真也没有影响。
  • 旋转对称物体（无把手的杯子、圆凳）：yaw 只影响纹理，直接用颜色项决定。

取得分前 3 的候选进入精对齐。

8.4 位置

  • z：mesh 底面贴合支撑面，tz = h_s。支撑物是另一个物体时，h_s 取该物体已放置的最终 mesh在本物体投影区域内的顶面高度（光线向下投射得到），不用高斯估计值。
  • xy 初值：可见高斯点的水平中心。部分可见时中心会偏向看得见的一侧，所以初值只是起点，由 8.5 的单向 Chamfer 纠正。
  • 靠墙约束：B/C 类物体的 mesh 不得穿入墙面。墙面是解析平面，计算 mesh 采样点到平面的有符号距离即可。

8.5 精对齐（CPU 方案）

两段式：先用约束 ICP 快速收敛，再用无梯度优化处理轮廓这种不可导的目标。

第一段：受约束 ICP（每个候选 ψ 各跑一次）

重复至收敛（最多 30 轮）：
  1. 每个高斯点 g 找 mesh 上最近点 m（KD 树）；丢掉距离 > 5 cm 的点对
  2. 只在水平面上解 2D 相似变换（Umeyama）：得到 Δψ, Δtx, Δty
     尺度固定为 s0，不在 ICP 里更新（部分观测下 ICP 求尺度不稳定）
  3. z 不更新，保持贴合支撑面
  4. |Δψ| < 0.1° 且 |Δt| < 1 mm 时停止

实现细节：mesh 的 KD 树建在规范系里只建一次，每轮把高斯点反变换到规范系再查询，不用每轮重建。

第二段：CMA-ES 全目标优化（只对 ICP 后得分最高的候选）

参数 θ = (s, ψ, tx, ty, tz)
  箱形家具（v0.2）：s 换成 (s_x, s_y, s_z)，每轴 ∈ s0·[0.88, 1.12]，
                    尺度正则项改为 0.2 · Σ((s_i − s0)/s0)²
  搜索范围：s ∈ s0·[0.9, 1.1]，ψ ± 10°，t ± 5 cm，tz ∈ h_s + [−5, +5] mm

L(θ) = 1.0 · D_G→M / diag                     单向 Chamfer（截断、归一化）
     + 1.0 · (1 − IoU_mean)                   K 视角轮廓，128 px
     + 2.0 · pen(θ)                           穿插：mesh 采样点进入墙、地面、场景 mesh、已放物体的深度之和 / diag
     + 1.0 · |z_min − h_s| / 0.01m            支撑缝隙
     + 0.2 · ((s − s0)/s0)² + 0.1 · ((ψ − ψ_ICP)/10°)²   不偏离先验太远

CMA-ES：种群 12，最多 40 代，约 500 次目标函数评估
单次评估约 30–60 ms → 每个物体 15–30 s（单核）

穿插计算（v0.2 重写）：v0.1 的做法是删除场景 mesh 中落在本物体 OBB（外扩 3 cm）内的面片，再用 compute_signed_distance 取负值作为穿入深度。实测证明这不可用：SLAM mesh 本来就不封闭，挖掉柜体后又多出一个大洞，内外判定失效。把 813 个真实相机位置送进去检查，795 个被判为"在几何体内部"，而相机显然都在空气里。这个错误的穿插项一直在把物体推偏：同样的初值，只在优化时去掉这一项，柜体平均 IoU 从 0.550 升到 0.779，Chamfer P90 从 101 mm 降到 48 mm。

改为按障碍物类型分别计算，不再对场景 SLAM mesh 求有符号距离：

障碍物穿入判定说明
墙面、地面解析平面的有符号距离可靠，不变
已放置物体对其最终 mesh 用广义绕数（generalized winding number）判内外，深度取到表面的无符号距离绕数对小洞、不封闭的 mesh 稳健；该物体是 L3 时用它的碰撞凸包
场景 mesh 的其余部分（未单体化的结构、被排除的固定部件）可见性判定：采样点投影到各真实视角，若在 ≥ 2 个视角中都位于观测表面之后 5 mm 以上，且在所有看得到它的视角中都不在观测表面之前，才计为穿入；深度取最小的"表面之后"距离，上限 5 cm只依赖"相机到观测表面之间是空气"这一可靠事实，不需要 mesh 封闭
  • 挖洞按实例而不是按 OBB：只删除最近高斯属于本物体实例的面片。按 OBB 外扩删除会误删相邻物体（例如柜面上的茶托），也会漏删伸出 OBB 的部分。
  • 穿插项上线前先自检：每个场景把真实相机中心当作测试点，判为"在内部"的比例 > 1% 时，该场景的场景 mesh 穿插项整体停用，只保留墙地平面和已放置物体两项，并标记 COLLISION_ORACLE_INVALID。

静置测试的一个用法：如果物体在 2 s 内稳定下来，且位移 < 2 cm、旋转 < 5°，直接采用稳定后的位姿作为最终位姿，可以自动消除微小的悬空或倾斜。

v0.2：关卡本身的前提条件

  • 指标有效性先于阈值：eval_mask 通过 8.1 的范围自检、IoU 视角有真实内参、穿插项通过相机自检，三者缺一时，对应指标记为"无效"而不是"不通过"，物体最高只能判 L2 候选，不能判 L1，也不触发重试。
  • 替换已有摆放时用相对标准：实测中原摆放自己的 IoU 也只有 0.74–0.83，达不到 0.85 的绝对阈值。有 T_WM_baseline 时，新结果在同一 eval_mask 上的 IoU 不低于原摆放 − 0.02、尺寸误差更小、穿插不更差，才允许替换；否则保留原摆放。绝对阈值仍用于没有原摆放的新物体，并在 E5 中用原摆放的分布重新校准。

现象最可能的原因处理
所有候选的 IoU 都 < 0.6生成的形状本身不对预算允许时回到 S6/S7 重新生成一次（换种子，修正问题视角）；否则 L2
部分视角 IoU 高，部分很低低分视角存在未检测到的遮挡，或 mask 有误剔除低分视角重算；剩余视角 < 2 个则降低置信度
x、y 尺度正好互换Rodin 正面朝向差 90°ψ 候选 ±90° 后重跑 8.3
尺度轴不一致且非互换生成比例不对≤ 5% 留给 S9 各向异性修正；> 5% 重新生成或 L2
贴墙穿插 > 5 mm深度方向生成过厚沿墙法线平移；仍需要压缩时，深度轴压缩 ≤ 5%；否则 L2
和已放置物体穿插支撑物 mesh 顶面不平，或支撑关系错误重新向下投射计算 h_s；仍穿插时检查 S2 支撑关系
静置测试倾倒底面不平，或重心落在支撑面外检查是否为倾倒物体（走倾斜角分支）；否则底面平整化后在 S9 重试

每个物体在 S8 最多重试 2 次（不含换候选角）。重试耗尽后：能从场景 mesh 裁出完整物体就转 L2，否则 L3。

  • v0.2：每次重试必须改变一个已诊断的原因（换视角、换尺度来源、剔除坏视角、改支撑高度……），并把原因写进记录。诊断不出新原因时不重试，直接降级。实测中床和柜体各重试两次都被拒，重试本身没有带来新信息。
  • v0.2：父物体降级时，子物体照常放置。实测中柜体失败后，茶托和两瓶水没有沿用错误的父物体姿态，这一点是对的；但它们因此直接进了 L3。改为：父物体降级后，子物体的 h_s 取父物体降级产物（L2 mesh 或 L3 碰撞体）的顶面，子物体独立走 S8，并标记 parent_degraded。父物体之后若重新放置成功，按 DAG 重新放置其子物体。

S9几何与纹理修复

几何：只做低频修正

  1. 对每个 mesh 顶点，计算到最近高斯点的距离，只统计可见区域（该顶点在至少一个可信视角中可见），得到误差热力图。
  2. 可见区域误差 P90 ≤ 1.5 cm：不修改。
  3. 误差偏大：先做每轴不超过 5% 的各向异性缩放；仍不够时，做 3×3×3 的 FFD 晶格形变，控制点位移不超过对角线的 3%，并加平滑项。只有可见区域的顶点参与约束，看不到的部分跟随晶格平滑变化。
  4. 修正后可见区域仍有 > 10% 面积误差 > 3 cm：不再强行修，预算允许就重新生成，否则保留当前结果并降低置信度。

不做逐顶点的高频非刚性形变：高斯本身有噪声，逐点贴合会把 mesh 拉坏，还会破坏 UV。

纹理：保留生成纹理的细节，只校正低频颜色

生成纹理更清晰，但颜色可能偏；高斯渲染颜色准，但模糊。所以把两者按频率拆开组合：

对每个纹素 p（对应 mesh 表面点 x）：
  1. 观测颜色 C_obs(p)：在可信视角中光线投射判断 x 是否可见（挖掉自身的场景 mesh + 自身 mesh）
     可见视角按 w = cos²(法线, 视线) · q_view 加权平均高斯渲染颜色
  2. 低通：在 mesh 表面上做测地邻域平滑（约 2 cm 半径），得到 LP(C_obs)、LP(C_gen)
  3. 在 Lab 空间计算修正量 Δ = LP(C_obs) − LP(C_gen)，只在有观测的区域
  4. 无观测区域（底面、贴墙面）：在 mesh 图上做调和插值，把 Δ 平滑延伸过去，避免接缝
  5. C_new = C_gen + Δ

注意 PBR 与烘焙光照：Rodin 的 PBR base color 是去光照的，高斯颜色带有采集时的场景光照。仿真引擎会自己打光，如果把场景光照完整烘焙进 base color，在仿真里会出现重复的阴影和高光。建议对 a、b 色度通道做完整校正，对亮度 L 通道限制在 ±15% 以内。

备选方案：调用 Rodin 的 rodin_texture_only 接口，传入 mesh 和高斯渲染图作为参考，在云端重新生成纹理。效果可能更好，但会增加成本，适合作为高价值物体的选项。

S10仿真封装与终检

  1. 网格修复：检查流形和封闭性，修复小洞，统一法线朝外。
  2. 视觉 mesh 减面：按面数预算减面（待确认仿真平台的预算）。
  3. 碰撞体：CoACD 凸分解，threshold = 0.05，最多 16 个凸包，超时 120 s。超时则退回 V-HACD，再不行用单个凸包。
  4. 物理属性：按语义标签查表得到密度、摩擦系数、恢复系数。空心物体（杯、碗、箱子）直接查质量先验，不用体积乘密度。
  5. 导出：USD / URDF / MJCF（待确认），统一写到场景资产包里，附带每个物体的 T_WM_final、等级、置信度。
  6. 场景级终检：所有物体一起放进物理引擎仿真 3 s。任何物体位移 > 2 cm 视为不稳定，回到 S8 微调；两两穿插检查。

幂等与断点续跑

  • 每一步的输出以 哈希(输入产物 + 参数 + 代码版本) 为键存储。任务重跑时，键已存在就直接跳过。
  • 外部调用先写"待提交"记录，再调用，成功后回写结果。进程中途崩溃时，按记录查询外部任务状态，不会重复付费。
  • 场景级超时（例如 6 小时）：未完成的物体全部转降级，场景照常交付。

常规判断不走 agent

"这张图有几个物体""这些视角是否一致"这类判断，直接调用模型 API 并使用结构化输出，一次调用返回 JSON。codex-app-server 每轮都有 token 开销和较高延迟，只用于异常诊断和开发期调参。
